## 🏗️ Current System Architecture

### **Data Flow**
```
User runs daily_notification.py (16:00)
    ↓
fetch_data() - Intelligent price sourcing
    ├─ Try Octopus API (48 hours)
    ├─ Check has_next_day_prices()?
    │   ├─ YES → Use actual ("octopus_actual")
    │   └─ NO  → fetch_forecast_prices() ("forecast")
    ↓
analyzer.find_optimal_window()
    ↓
Save recommendation with:

    - day_type ("weekday"/"weekend")
    - price_source ("octopus_actual"/"forecast")
    - window_start, window_end
    - rating, cost, carbon, etc.

    ↓
format_notification()

    - Check window.get_status() (ACTIVE/PASSED/UPCOMING)
    - Add status-aware messaging
    - Show data source indicator

    ↓
Send Pushover notification
```

### **Key Modules**
- **octopus_api.py** - Fetches actual Octopus Energy prices
- **forecast_api.py** - Scrapes Guy Lipman forecasts (fallback)
- **carbon_api.py** - Fetches National Grid carbon intensity
- **analyzer.py** - Window analysis, scoring, status detection
- **data_store.py** - JSON-based persistence
- **pushover.py** - Push notifications
- **forecast_tracker.py** - Tracks forecast accuracy over time
- **threshold_tuner.py** - Auto-tunes thresholds to market conditions

### **Scripts**
- **daily_notification.py** - Main recommendation engine (runs 16:00)
- **charge_reminder.py** - Evening reminder (runs 20:00)
- **weekly_forecast.py** - 7-day forecast (runs Monday 07:00)
- **weekly_summary.py** - Performance review (runs Sunday 18:00)
- **log_charge.py** - Manual charge logging tool
